**آخر تحقق:** 2026-11-07. خطوات الرفع والرجوع بالتفصيل في [`DEPLOYMENT.md`](DEPLOYMENT.md)، والسيرفرات في [`SERVER_ARCHITECTURE.md`](SERVER_ARCHITECTURE.md).

## 1. اللي شغال
| الحاجة | إزاي | الملف |
|---|---|---|
| فحص كل تعديل | GitHub Actions على أجهزة GitHub: tsc واختبارات الخادم، وanalyze واختبارات التطبيق | `.github/workflows/checks.yml` |
| الرفع | push على `main` ← runner السيرفر الجديد ← فحص ← `deploy.sh` | `.github/workflows/deploy.yml` و`backend/deploy.sh` |
| الرجوع | تلقائي لو النسخة الجديدة ما ردّتش، أو يدوي بالتاج أو `.previous` | `deploy.sh` |
| نسخة قبل الرفع | `pg_dump` + الكود | `deploy.sh` |
| تغييرات القاعدة | migrations بأرقام، بتشتغل مع تشغيل الخادم مرة واحدة | `backend/migrations`، و`src/database/migrate.ts` |
| الإعدادات والأسرار | `.env` على السيرفر بس، والقيم مش في الريبو | `src/config/index.ts` |
| الخرايط | حاويتين Docker على القديم، ورسم الكاش بسكريبت | `backend/map-services` |

> **2026-11-07:** `checks.yml` **متوقف بقرار صاحب المشروع**: حساب GitHub موقوف لمشكلة دفع، ومش عايز يضيف كارت. الحماية دلوقتي: فحص الخادم (tsc والاختبارات) على runner سيرفرنا قبل كل رفع، وفحص التطبيق على جهاز التطوير قبل كل commit (إلزامي). يرجع بإضافة `push:` في الملف لما الحساب يتظبط.

## 2. قرارات
- **الخادم من غير Docker:** systemd بيشغّله ويرجّعه لو وقع، والرفع بيبدّل الـ workers من غير وقوع. Docker هنا هيضيف طبقة من غير فايدة دلوقتي. الخرايط في Docker لأنها برامج جاهزة.
- **مفيش سيرفر تجريبي:** التجربة محليًا بالاختبارات (PGlite والخادم الوهمي) وبمعاينة اللوحة. لما يبقى فيه مستخدمين، سيرفر تجريبي صغير هيبقى مطلوب قبل أي تغيير كبير.
- **الفحص على أجهزة GitHub مش سيرفرنا:** عشان الريبو عام وrunner الإنتاج عندنا.
