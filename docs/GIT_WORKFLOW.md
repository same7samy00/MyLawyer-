# طريقة الشغل على Git

**آخر تحقق:** 2026-11-07. الريبو `same7samy00/MyLawyer-` **عام**.

## 1. الفروع
| الفرع | لازمته |
|---|---|
| `main` | الإنتاج. أي push عليه فيه `backend/**` بيرفع على السيرفر الجديد |
| `claude/<المهمة>` و`gemini/<المهمة>` | الشغل. واحد لكل مهمة |
| `master` (محلي بس) | تاريخ قديم فيه أسرار. **ممنوع يترفع أبدًا** |
| `map-test` (محلي) | تجربة قديمة. ما يتمسحش غير بإذن |

## 2. دورة المهمة
1. فرع من `main` المحدّث.
2. commits صغيرة واضحة، والرسالة بالإنجليزي وتقول إيه اللي اتغير ولية.
3. قبل كل commit: `git status`، ومفيش `git add .`، ومفيش أي ملف من `.access` أو `.env` أو مفاتيح.
4. الفحوصات (`docs/TESTING.md`) قبل ما تقول «خلصت».
5. الرفع والدمج في `main` بعد «ارفع» من صاحب المشروع بس (`docs/DEPLOYMENT.md`).

## 3. نقط الرجوع
- قبل أي مرحلة كبيرة أو رفع: `git tag checkpoint/before-<اسم>`.
- الرجوع بـ `git revert` أو بالتاج.
- ممنوع من غير موافقة: `push --force`، و`reset --hard`، و`rebase` على فرع اترفع، ومسح فروع، وتغيير إعدادات الريبو.

## 4. الفحص التلقائي
`.github/workflows/checks.yml` بيفحص التطبيق والخادم مع كل push على أي فرع، على سيرفرات GitHub (مش سيرفرنا). مفيش تشغيل لطلبات الدمج من نسخ تانية من الريبو، لأن runner الإنتاج على سيرفرنا.
